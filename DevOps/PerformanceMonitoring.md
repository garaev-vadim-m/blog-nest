## Performance Monitoring

#### Смотрим память

```bash
free -h
```

`total` — всего RAM на машине: 7.7GB

`used` — реально занято процессами: 1.8GB

`free` — совсем свободно: 4.5GB

`buff/cache` — занято кешем ядра: 1.4GB. Это не потеря — Linux специально кеширует диск в RAM для скорости. При нехватке памяти ядро этот кеш освобождает автоматически.

`available` — реально доступно для новых процессов: 5.7GB. Это free + buff/cache. Вот на эту цифру смотришь в первую очередь.

#### Смотрим место на диске

```bash
df -h
```

`overlay` — это файловая система самого Docker контейнера.

`tmpfs` — виртуальные файловые системы в памяти, только для чтения ядра.

`На Use% смотришь в первую очередь` — если больше 85-90% то пора чистить.

Главные колонки по устройствам:

```bash
r/s   — чтений в секунду
w/s   — записей в секунду
%util — загруженность диска (главный показатель)
```

Все нули потому что контейнер сейчас ничего не делает.

На реальном сервере под нагрузкой %util выше 80% — тревожный сигнал, диск становится узким местом.

Итого по Performance Monitoring:

```bash
free -h       — память, swap
df -h         — место на диске
vmstat 1 5    — память, swap, CPU в динамике
iostat -x 1 3 — нагрузка на диск
top           — всё вместе в реальном времени
```

На реальном сервере смотреть в первую очередь:

`free` — если `available` меньше 10% — проблема
`vmstat` — если `so` (swap out) не 0 — проблема
`iostat` — если `%util` больше 80% — проблема
`top` — если `load average` больше числа ядер CPU — проблема
